# 프로젝트 계획서: 야구 경기 일정 한눈에 보기

- 작성일: 2026-10-30 (3주차)
- 배포 주소: https://kbo-schedule.vercel.app/
- GitHub: https://github.com/frogbear4879-wq/kbo-schedule
- 관련 문서: `PRD.md`(요구사항), `docs/poc.md`(PoC 점검 기록), `docs/learning.md`(localStorage 학습 노트), `docs/todo.md`(향후 작업 목록)

> **데이터 안내:** 배포 사이트가 보여주는 경기 일정과 점수는 **시연용 가상 데이터**(2026-09-08~09-20, 60경기)이며 **실제 KBO 경기 일정과 결과가 아니다.** 실제 2026 경기 데이터는 로컬 개발용으로만 쓰고 공개 배포에 포함하지 않는다.

## 1. 프로젝트 목표
경기 일정과 우천취소 같은 변경 소식이 여러 곳에 흩어져 있어 확인이 번거롭고, 변경을 늦게 알면 피해가 생긴다(팬: 교통비·숙박비·시간 낭비, 구장 근처 상인: 불필요한 준비 손해). 이를 **한 화면에서 일정과 경기 상태를 확인할 수 있는 웹사이트**로 해결하는 것이 목표다.

- 대상 사용자: 지방에서 원정 직관을 가는 팬, 구장 근처 상인, 일반 야구 팬
- 이번 학기 목표(PoC): 2주 안에 구현 가능한 범위로, 일정 조회와 응원팀 강조를 중심으로 동작하는 사이트를 배포하고 점검한다.
- 이번 범위 밖: 티켓 예매, 실시간 중계, 일반 사용자 로그인, 해외 리그, AI 취소 예측, 취소 자동 감지와 푸시 알림 보장

## 2. 핵심 사용자 시나리오
1. **일정 확인:** 사용자가 사이트에 접속하면 첫 주 일정이 보인다. 주간/월간 보기를 바꾸고 ◀ ▶로 기간을 이동한다.
2. **내 팀 강조:** 응원팀(10개 구단)을 고르면 그 팀 경기가 ★와 테두리로 강조된다. 다시 접속해도 선택이 유지된다.
3. **경기 상태 확인:** 각 경기가 예정·종료·취소·연기 중 어느 상태인지 색상과 글자로 구분해 보고, 종료된 경기는 최종 점수를 확인한다.
4. **경기 상세:** 경기 카드를 누르면 날짜·시간·구장·상태·양 팀·최종 점수를 상세 화면에서 본다.
5. **오류 상황:** 데이터 파일에 문제가 있어도 화면이 멈추지 않고 안내 문구가 나온다.

## 3. 데이터 출처 및 제한
| 구분 | 내용 |
|---|---|
| **배포용 데이터** | `data/demo_games.csv`: 직접 만든 **시연용 가상 데이터** 60경기(종료 42, 취소 2, 연기 1, 예정 15). 팀 이름만 실제 구단이고 일정·점수·상태·구장(`시연구장(팀명)`)은 모두 가상이다. 화면 상단 배너, 푸터, 상세 화면에 가상 데이터 안내를 표시한다 |
| **실제 데이터(로컬 전용)** | 2026 정규시즌 793건(종료 720, 취소 73)을 `data/kbo_2026_full.csv`로 변환해 로컬 개발·기능 확인에만 사용. `.gitignore`·`.vercelignore`로 GitHub와 배포에서 제외하며, 배포 주소에서 해당 파일과 원본 JSON은 404임을 확인했다 |
| 실제 데이터 출처 | https://github.com/dentearl/kbo-data (`data/kbo/2026.json`): 일정·상태·최종 점수만 제공 |
| **이용 권한 제한** | 위 저장소에는 **라이선스가 명시되어 있지 않아** 재사용·재배포 권한을 확인하지 못했다. 저장소는 KBO 사이트를 자동 수집해 만들어지는데, KBO 사이트의 `robots.txt`는 사전 승인 없는 자동 수집·복제를 금지한다. 그래서 **재배포가 허용된다고 판단하지 않았고** 공개 배포에는 쓰지 않는다 |
| 상세 기록 | KBO 공식 게임센터의 상세 기록(이닝별 점수·선수 기록)은 같은 이유로 수집하지 않았다. 따라서 이닝별·선수별 기록은 데이터가 없다 |
| 실제 데이터의 한계 | 구장은 원본에 없어 홈팀 연고 구장으로 채운 추정값이고, 취소·연기는 원본에서 구분되지 않아 `isCancelled` 값에 따라 취소로 분류했다(로컬 한정) |
| 확장 시 조건 | 실제 데이터로 서비스하려면 KBO 또는 데이터 제공처의 이용 허가를 먼저 받아야 한다 |

## 4. 사용 기술
| 영역 | 기술 |
|---|---|
| 화면 | HTML, CSS, JavaScript (프레임워크·빌드 도구 없음) |
| 데이터 | CSV 파일을 브라우저에서 `fetch`로 읽어 화면 구성 |
| 저장 | 응원팀을 브라우저 `localStorage`에 저장(서버 저장 없음, 학습 내용은 `docs/learning.md`) |
| 배포 | GitHub → Vercel 무료(Hobby) 정적 호스팅(개인·비상업적 용도) |
| 로컬 실행 | `node server.js` 후 http://localhost:5500 |
| 사용하지 않는 것 | 공용 DB, 서버, 로그인, 날씨 API |

## 6. 검증 방법과 현재 결과
- **기준:** `PRD.md` 7장 완료 기준 8개를 그대로 사용한다(`docs/poc.md`).
- **방법:** (1) 사용자가 브라우저에서 직접 점검한 6개 항목(접속, 주간/월간 전환, 구단 선택, 상세정보, 새로고침 후 유지, 가상 데이터 안내), (2) 내장 브라우저로 배포 주소를 PC(1280×800)·모바일(375×812 에뮬레이션)에서 자동 점검. Playwright는 설치하지 않아 사용하지 않았다.
- **결과(2026-10-30):** 통과 5건(첫 화면, 3초 이내[1개 환경 한정], 팀 강조·유지, 상태 4종, CSV 오류 안내[부분 방법]), 실패 2건(관리자 상태 변경, 변경 알림: 미구현), 미검증 1건(공용 DB).
- **아직 검증하지 않은 것:** 저속망·실제 휴대폰·여러 브라우저에서의 표시와 로딩 시간, 배포된 CSV 파일 자체를 오류 파일로 바꾼 시험. 이 항목은 통과로 처리하지 않았다.
- **관찰된 문제:** (1) `?data=real` 주소에서 실제 데이터가 있는 것처럼 보이는 안내, (2) 모바일 월간 보기 길이(약 6,600px), (3) 상세 화면의 "기록 없음" 반복.

## 8. 위험과 대응
| 위험 | 대응 |
|---|---|
| 실제 데이터의 이용 권한이 불분명하다 | 공개 배포에는 시연용 가상 데이터만 사용, 실제 데이터는 로컬 전용으로 유지 |
| 가상 데이터를 실제 일정으로 오해할 수 있다 | 배너·푸터·상세 화면에 안내 표시, 발표 시작 때 말로도 밝힘 |
| 남은 수업 시간이 부족하다 | 발표 필수와 선택 작업을 구분, 관리자·DB·알림은 확장으로 분리 |
| 발표 중 접속 문제 | 스크린샷과 로컬 실행(`node server.js`)을 대비책으로 준비 |
