## 0. 가장 먼저 알아둘 점: 이 사이트의 데이터는 시연용 가상 데이터
**배포 사이트가 보여주는 경기 일정과 점수는 시연용 가상 데이터이며, 실제 KBO 경기 일정과 결과가 아니다.**
- 데이터: `data/demo_games.csv` (2026-09-08~09-20, 가상 60경기: 종료 42, 취소 2, 연기 1, 예정 15). 구장도 `시연구장(팀명)`이라는 시연용 이름이다.
- 실제 2026 경기 데이터는 로컬 개발용이며 GitHub와 배포에 포함되지 않는다. 배포 주소에서 `/data/kbo_2026_full.csv`와 `/data/raw/kbo_2026_source.json`은 모두 404였다(자동 점검으로 확인).
- 따라서 아래 "통과"는 **가상 데이터로 기능이 동작함**을 뜻하며, 실제 경기 정보의 정확성이나 최신성을 검증한 것이 아니다.

### 3-1. 로딩 시간 측정 (기준 2번)
| 측정 | 결과 |
|---|---|
| 첫 방문(캐시 없음) | `load` 이벤트 1,467ms, 일정 CSV 수신 완료 1,622ms (CSV 전송량 약 1.2KB) |
| 재방문(브라우저 캐시 재검증) | `load` 50~107ms, CSV 수신 완료 66~107ms, 첫 페인트 108ms |
| 캐시 우회로 4개 파일(HTML·CSS·JS·CSV) 동시 요청 3회 | 23~37ms |
| 전체 파일 크기 | HTML 약 2.7KB, CSS 약 8.4KB, JS 약 18KB, CSV 약 3.4KB (모두 합쳐도 약 33KB) |

- 일정이 화면에 그려지는 시점은 "CSV 수신 직후 렌더링"이므로 **CSV 수신 완료 시간으로 근사**했다. 일정 카드가 실제로 그려진 시각을 직접 측정한 값은 아니다.
- 한 번의 점검 세션에서 본 값이며(첫 방문 1회), 통계적으로 반복 측정하지 않았다.
- 점검 중 한 번 페이지가 비표시 상태였을 때 첫 페인트가 8.7초로 기록된 적이 있다. 창이 보이지 않아 페인트가 지연된 영향으로 판단해 **이 값은 제외**했다(화면이 보이는 상태에서 다시 측정한 값이 위 표의 값).
- **미검증으로 남는 것:** 저속 이동통신망, 실제 휴대폰, 다른 지역·시간대, 여러 번 반복한 평균. 이 문서의 "통과"는 위 한 환경에서 3초 이내였다는 뜻이다.

### 3-2. CSV 오류 처리 (기준 7번)
- **오류 줄 건너뛰기:** 배포 코드의 CSV 처리 함수에 5줄짜리 오류 CSV(정상 1줄 + 잘못된 날짜·모르는 팀·모르는 상태·빈 값 각 1줄)를 넣었더니, 정상 1줄만 읽고 오류 4줄에 대한 안내 문구(줄 번호와 이유)를 만들었다. 이어서 화면을 다시 그렸을 때 일정표가 깨지지 않고 1경기를 표시했고, 상단에 안내 문구가 표시됐다.
- **헤더 누락/빈 CSV:** 필요한 컬럼이 없다는 안내, 경기 데이터가 없다는 안내가 각각 나왔다.
- **파일 로드 실패:** 배포 주소에 `?data=real`을 붙이면 실제 CSV가 없어 404가 되는데, 이때 오류 안내가 표시되고 페이지(구단 선택, 월간 전환 등)는 계속 동작했다.
- **한계:** 배포된 `demo_games.csv` 자체를 오류가 있는 파일로 바꿔서 시험한 것은 아니다(데이터와 코드를 수정하지 않는다는 조건 때문). 그래서 "부분 방법"으로 표기했다.

### 3-3. 판정 요약
- **통과 5건**(1·2·3·4·7). 이 중 2번(3초 이내)은 1개 환경 한정, 7번(CSV 오류)은 부분 방법이라는 단서가 붙는다.
- **실패 2건**(5·8): 기능이 구현되어 있지 않다.
- **미검증 1건**(6): 공용 DB가 없어 검증할 수 없다.
- 실패 2건과 미검증 1건은 PRD가 이미 "미구현 및 향후 개발 계획"으로 적어 둔 항목과 일치한다.

## 5. 직접 관찰한 문제
1. **`?data=real` 주소의 안내가 헷갈린다.** 배포 사이트 주소 끝에 `?data=real`을 붙이면 탭 제목이 "(로컬 개발용 실제 데이터)"로 바뀌고 푸터에 "실제 2026 데이터(출처…) 공개 배포 금지"라고 나오며 시연 배너는 사라진다. 실제 데이터는 없어서 일정이 비어 있고 오류 안내만 나온다. 일반 사용자가 이 주소로 들어갈 일은 드물지만, 발표 중 실수로 열면 혼란스럽다.
2. **월간 화면이 모바일에서 매우 길다.** 월간 보기가 약 6,600px이고, 경기가 있는 12일을 모두 세로로 펼친다.
3. **경기 상세 화면의 정보가 적다.** 이닝별 점수 칸에 "기록 없음"이 표시되고, 선수별 기록 탭은 숨겨져 있다. 의도된 범위이지만 사용자는 카드를 눌러도 새로 얻는 정보가 거의 없다.

## 6. 사용자 입장에서의 불편한 점 3개와 개선 제안
아래 3개는 **개선 제안**이다. 앞의 "직접 관찰한 문제"와 연결되는 부분은 관찰 근거를 함께 적었다. 사용자 인터뷰나 실사용 테스트를 한 것은 아니다.

1. **[개선 제안] 응원팀 경기만 모아 보는 필터가 필요하다.**
   - 관찰 근거: 팀을 선택해도 모든 팀의 경기가 그대로 보이고, 내 팀 경기는 ★ 표시와 테두리로만 구분된다. 모바일에서는 한 주에 30경기가 3,700px에 걸쳐 나열되어 내 팀 경기를 찾으려면 스크롤해야 한다.
   - 제안: "내 팀 경기만 보기" 스위치를 추가하고, 선택 시 경기가 없는 날은 접어서 보여준다.
2. **[개선 제안] 모바일에서 월간 보기의 길이를 줄이고 안내 배너 높이를 낮춘다.**
   - 관찰 근거: 모바일 월간 보기 약 6,600px, 고정 배너가 화면 높이의 약 11%(90px)를 항상 차지한다.
   - 제안: 월간은 달력 격자(날짜별 경기 수·내 팀 경기 표시)로 보여주고 날짜를 누르면 목록을 펼친다. 배너는 스크롤 후 한 줄로 줄이거나 접을 수 있게 한다(가상 데이터 안내는 상세 화면과 푸터에도 있어 유지된다).
3. **[개선 제안] 오늘·내 팀 경기로 바로 이동하는 방법이 필요하다.**
   - 관찰 근거: 시연 모드에서는 항상 데이터의 첫 주(9/7~13)로 시작하고, 다른 주에서 처음으로 돌아가는 버튼이 없다. 응원팀을 골라도 해당 팀의 다음 경기 위치로 이동하지 않는다.
   - 제안: "이번 주/오늘" 버튼과 "내 팀 다음 경기로 이동" 버튼을 추가한다(실제 데이터를 쓸 때 특히 유용하다).

## 7. 미검증·남은 항목
- 저속망·실제 휴대폰·여러 브라우저에서의 로딩 시간과 표시(3초 기준의 폭넓은 검증)
