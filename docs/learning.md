# 학습 노트: JavaScript localStorage

> 주제: 브라우저에 데이터를 저장하는 `localStorage`
> 프로젝트: 야구 경기 일정 한눈에 보기 (https://kbo-schedule.vercel.app/)
> 아래 코드는 이 프로젝트의 `app.js`에서 실제로 확인한 내용이고, 동작 확인 결과도 실제로 해 본 것만 적었다.

## 1. localStorage가 뭘까?
`localStorage`는 **브라우저 안에 작은 메모장을 하나 두는 기능**이다. 웹사이트가 이 메모장에 글자를 적어 두면, 페이지를 새로고침하거나 브라우저를 껐다 켜도 그 글자가 남아 있다.

- 서버나 데이터베이스 없이 쓸 수 있다.
- "이름표(key) → 값(value)" 형태로 저장한다. 사물함에 이름표를 붙여 물건을 넣는 것과 비슷하다.
- 값은 **글자(문자열)만** 저장된다.
- 이 사이트(주소)가 저장한 것은 이 사이트만 꺼내 볼 수 있다.

자주 쓰는 명령은 세 가지다.
```js
localStorage.setItem("이름표", "값");   // 저장
localStorage.getItem("이름표");         // 꺼내기 (없으면 null)
localStorage.removeItem("이름표");      // 지우기
```

## 2. 우리 프로젝트에서는 어디에 썼나?
**응원팀(즐겨찾기 구단)을 기억하는 데** 썼다. 사용자가 상단의 "응원팀" 목록에서 구단을 고르면 이름(예: `NC`)을 `localStorage`에 저장하고, 다음에 사이트를 열면 그 이름을 꺼내서 같은 구단을 자동으로 선택해 준다. 그래서 다시 들어와도 내 팀 경기가 강조되어 있다.

관련 코드는 `app.js`의 세 군데에 있다.

| 역할 | 위치 | 하는 일 |
|---|---|---|
| 이름표 정하기 | `STORAGE_KEY` (29행) | 저장할 때 쓸 이름표를 `"myTeam"`으로 정함 |
| 불러오기 | `loadMyTeam()` (257행) | 저장된 팀 이름을 꺼냄 |
| 저장하기 | `saveMyTeam()` (265행) | 팀 이름을 저장 |

## 3. 핵심 코드와 쉬운 해설

### (1) 이름표 정하기
```js
const STORAGE_KEY = "myTeam"; // 응원팀을 브라우저에 저장할 때 쓰는 이름
```
저장할 때와 꺼낼 때 **같은 이름표**를 써야 한다. 오타를 막으려고 이름표를 변수 하나에 모아 두었다.

### (2) 저장하기
```js
function saveMyTeam(team) {
  try { localStorage.setItem(STORAGE_KEY, team); } catch (e) { /* 무시 */ }
}
```
- `setItem("myTeam", "NC")`처럼 이름표와 팀 이름을 함께 넣는다.
- `try ... catch`는 "혹시 저장이 안 되는 환경이어도 사이트가 멈추지 않게" 해 주는 안전장치다. 저장에 실패하면 그냥 넘어간다.

### (3) 불러오기
```js
function loadMyTeam() {
  try {
    const saved = localStorage.getItem(STORAGE_KEY);
    return TEAMS.includes(saved) ? saved : "";
  } catch (e) {
    return ""; // 저장소를 쓸 수 없는 환경이면 그냥 무시
  }
}
```
- `getItem("myTeam")`로 저장된 값을 꺼낸다. 처음 방문이라 저장된 게 없으면 `null`이 나온다.
- `TEAMS.includes(saved)`는 "꺼낸 값이 10개 구단 이름 중 하나가 맞는지" 확인한다. 맞으면 그 이름을 쓰고, 아니면 빈 값(`""`, 선택 안 함)을 쓴다. 누군가 저장된 값을 이상하게 바꿔 놔도 사이트가 이상해지지 않게 하려는 확인이다.
- 여기에도 `try ... catch`가 있어서 저장소를 못 쓰면 "선택 안 함"으로 시작한다.

### (4) 사용 시점: 처음 열 때와 구단을 고를 때
```js
// 사이트가 시작될 때 (init 함수 안)
TEAMS.forEach((t) => teamSelect.add(new Option(t, t)));  // 구단 목록 채우기
state.myTeam = loadMyTeam();                              // 저장된 팀 꺼내기
teamSelect.value = state.myTeam;                          // 목록에서 그 팀 선택

// 사용자가 구단을 바꿀 때
teamSelect.addEventListener("change", () => {
  state.myTeam = teamSelect.value;   // 지금 선택한 팀을 변수에 기억
  saveMyTeam(state.myTeam);          // localStorage에도 저장
  render();                          // 화면을 다시 그려서 내 팀 경기 강조
});
```
순서를 보면, 먼저 목록에 구단 10개를 채운 다음에 저장된 팀을 선택한다. 목록에 없는 값은 고를 수 없기 때문이다.

## 4. 새로고침해도 선택이 유지되는 원리
1. 사용자가 응원팀을 `NC`로 고른다.
2. `change` 이벤트가 일어나서 `saveMyTeam("NC")`가 실행되고, 브라우저의 `localStorage`에 `myTeam = NC`가 저장된다.
3. 새로고침하면 페이지의 JavaScript 변수는 모두 사라지지만, `localStorage`에 적어 둔 값은 **브라우저에 남아 있다.**
4. 페이지가 다시 열리면 `loadMyTeam()`이 `myTeam` 값을 꺼내 `NC`를 얻고, 목록을 `NC`로 선택한 뒤 화면을 그린다.

즉 "변수는 새로고침하면 사라지고, localStorage는 남는다"가 핵심이다. 이 프로젝트에서 `state.myTeam` 변수는 화면을 그릴 때 쓰고, `localStorage`는 다음 방문을 위해 기억해 두는 용도로 나눠 썼다.

### 실제로 확인한 것
- 배포 사이트(https://kbo-schedule.vercel.app/)에서 NC를 선택하면 `localStorage`의 `myTeam` 값이 `NC`가 되는 것을 자동 점검에서 확인했다.
- 페이지를 다시 열었을 때 NC가 선택되어 있고 NC 경기 6경기가 강조되는 것도 확인했다(PC와 모바일 크기 모두). 자세한 점검 기록은 `docs/poc.md`에 있다.
- 사용자의 직접 점검에서도 "새로고침 후 즐겨찾기 유지"가 완료되었다고 보고받았다.

## 5. 프로젝트를 만들며 배운 점 3가지
1. **저장된 값은 믿지 말고 확인하고 꺼내 쓴다.** `localStorage`에서 꺼낸 값은 사용자가 바꿀 수도 있고, 처음엔 아예 없을 수도 있다(`null`). 그래서 `loadMyTeam()`에서 10개 구단 이름 중 하나인지 확인하고, 아니면 "선택 안 함"으로 처리했다.
2. **저장이 안 되는 상황도 생각해야 한다.** 코드에 `try ... catch`를 넣은 이유는 브라우저 설정에 따라 저장소를 못 쓸 수도 있기 때문이다. 저장이 안 되더라도 구단 선택과 일정 보기는 계속 동작하고, 단지 새로고침하면 선택이 초기화될 뿐이다. (이 "못 쓰는 상황"을 실제로 재현해 본 것은 아니고, 코드를 이렇게 작성했다는 것까지만 확인했다.)
3. **같은 사이트라도 주소가 다르면 저장소가 따로다.** 이 프로젝트를 내 PC(`localhost`)에서 테스트하고 배포 사이트(`vercel.app`)를 처음 열었을 때, 배포 사이트의 `myTeam` 값은 비어 있었다(`null`). 내 PC에서 NC를 골랐어도 배포 사이트는 그 값을 모른다. 그래서 "처음 방문"에서는 항상 구단 선택이 비어 있는 것이 정상이다. 반대로 말하면 사용자가 바뀌거나 다른 기기에서 열면 선택이 따라오지 않는다.

## 6. localStorage의 한계와 주의사항
- **글자만 저장된다.** 숫자나 목록을 저장하려면 글자로 바꿔야 한다(예: `JSON.stringify`). 이 프로젝트는 팀 이름(글자) 하나만 저장해서 필요 없었다.
- **저장 용량이 작다.** 보통 도메인당 몇 MB 정도로 알려져 있다(브라우저마다 다름). 큰 데이터를 저장하는 용도가 아니다. 이 프로젝트에서는 용량 한도를 시험해 보지 않았다.
- **그 브라우저에만 저장된다.** 다른 기기나 다른 브라우저, 다른 사람에게는 공유되지 않는다. 그래서 PRD의 "다른 사용자 화면에 반영" 같은 기능에는 `localStorage`가 아니라 서버나 데이터베이스가 필요하다(이 프로젝트에서는 아직 구현하지 않음).
- **지워질 수 있다.** 사용자가 사이트 데이터를 지우거나, 시크릿(비공개) 창을 쓰거나, 브라우저 설정에 따라 저장이 안 되거나 사라질 수 있다. 중요한 정보를 저장하는 곳으로는 알맞지 않다. (시크릿 창에서의 동작은 직접 시험해 보지 않았다.)
- **보안 정보를 넣지 않는다.** 비밀번호, 로그인 토큰 같은 민감한 정보는 저장하지 않는 것이 안전하다. 같은 사이트의 JavaScript는 모두 읽을 수 있기 때문이다. 이 프로젝트는 응원팀 이름만 저장한다.
- **동기 방식이라 많이 쓰면 느려질 수 있다.** 작은 값을 가끔 읽고 쓰는 용도에 적합하다.

## 7. 정리
`localStorage`는 "서버 없이, 이 브라우저에, 작은 글자를 오래 기억하게 하는" 가장 간단한 방법이다. 우리 프로젝트에서는 응원팀 이름 하나를 `setItem`으로 저장하고 `getItem`으로 꺼내, 새로고침 후에도 내 팀 경기가 강조되도록 했다. 대신 그 브라우저에만 저장된다는 한계가 있어서, 여러 사용자가 공유하는 정보는 서버나 데이터베이스가 필요하다.
