### 점검에서 직접 관찰한 문제 (poc.md 5장)
- **P1** `?data=real` 주소를 열면 "로컬 개발용 실제 데이터"라는 제목·푸터가 나오지만 실제 데이터는 없어 일정이 비고 오류 안내만 뜬다. 실제 데이터가 있는 것처럼 보여 혼란스럽다.
- **P2** 모바일 월간 보기가 약 6,600px로 매우 길다.
- **P3** 상세 화면이 "기록 없음"만 반복되어 새로 얻는 정보가 적다.

### 개선 제안 (poc.md 6장, 실사용 테스트로 확인한 것은 아님)
- **S1** 응원팀 경기만 보기 필터
- **S2** 모바일 월간 압축 + 고정 배너 높이(90px, 화면의 약 11%) 줄이기
- **S3** 오늘 / 내 팀 다음 경기로 이동하는 버튼

## 6. 발표 필수 기능 vs 향후 확장 기능

남은 수업 시간(4주차 1회, 5주차 1회는 발표 준비 중심)을 고려한 구분이다.

### 이번 발표 필수 (이미 구현 + 4주차 전·4주차 작업)
- 구현 완료: 주간·월간 보기, 응원팀 선택·강조·새로고침 후 유지, 경기 상태 4종, 종료 경기 점수, 경기 상세 화면, 가상 데이터 안내
- 수정 필수: T1(`?data=real` 안내), T2·T3(상세 화면 간결화), T7·T8(모바일 월간)
- 발표 준비 필수: T16~T20(최종 점검, PRD 갱신, 발표 구성, 시나리오, 연습)

### 시간이 되면 (발표 품질 향상)
- T9 내 팀 경기만 보기 필터, T10·T11 이동 버튼, T12 배너 높이, T13 주간 정리, T5 실제 휴대폰 점검

### 향후 확장 (이번 발표 범위 밖, 현재 미구현)
| 항목 | 현재 상태 | 시작하려면 필요한 것 |
|---|---|---|
| 관리자 경기 상태 변경 | **미구현** | 관리자 화면, 저장 방식, 인증 방식 결정 |
| 공용 DB(예: Supabase) 연결 | **미구현** | 계정·프로젝트 생성, 접근 권한과 키 관리 설계 |
| 변경 알림(사이트 내 알림·이메일) | **미구현** | 관리자 기능과 DB가 먼저 필요 |
| 구장별 날씨(기상청 단기예보 API) | **미구현** | 공공데이터포털 API 활용 신청, 키 관리, 구장별 좌표 |
| 이닝별 점수·선수별 기록·교체 내역 | **미구현**(탭 코드만 있음, 숨김) | 이용이 허용된 데이터 출처 확보 |
| 실제 KBO 데이터 공개 서비스 | **보류** | 데이터 제공처·KBO의 이용 허가 확인(현재는 허용 여부 불명확) |

발표에서는 위 확장 기능을 "구현했다"고 말하지 않고 **"미구현이며 향후 계획"**으로 설명한다. 관리자·DB·알림은 서로 연결된 기능이라 한 번에 만들기에는 남은 시간이 부족하다고 판단했다.
